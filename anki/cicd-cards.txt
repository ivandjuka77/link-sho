In Docker Compose, which flag makes <code>docker compose up -d</code> block until all services are healthy?	<code>--wait</code><br>Example: <code>docker compose up -d --build --wait</code><br>It uses the healthchecks. Exit code 0 means all services are healthy. Non-zero means one failed or never became healthy. Useful in CI before smoke tests.	docker compose cicd
Which curl option prints only the HTTP status code, with no body?	<code>-w '%{http_code}'</code> (with <code>-o /dev/null -s</code>)<br>Example: <code>curl -s -o /dev/null -w '%{http_code}' http://localhost:8080/abc123</code><br><code>-w</code> prints a format string after the request. <code>-o /dev/null</code> throws away the body. <code>-s</code> hides the progress bar. Useful in CI to compare against an expected status like 302.	curl cicd
What is Docker Buildx, and why does <code>docker/setup-buildx-action</code> come before <code>docker/build-push-action</code> when you use <code>type=gha</code> caching?	Buildx is Docker&#39;s newer build tool, running on BuildKit.<br>The default runner builder cannot export a cache to GitHub storage. The setup action creates a <code>docker-container</code> builder that can.<br>Other uses: multi-platform builds (amd64 + arm64), exporting caches to a registry or local folder, parallel builds.	docker cicd buildx
In <code>build-push-action</code>, what is the difference between <code>context</code> and <code>scope</code>?	<code>context</code> is a normal input. It is the folder Docker builds from (the files <code>COPY</code> can see). Example: <code>context: backend</code><br><code>scope</code> is a key inside <code>cache-from</code> / <code>cache-to</code>. It is the name of a cache slot. Same scope = shared slot. Different scope = separate slots.<br>Two images in one job need separate scopes (<code>scope=backend</code>, <code>scope=frontend</code>). Writing <code>context=</code> inside the cache string is ignored silently, so both builds share one slot, overwrite each other, and the cache keeps missing.	docker cicd cache
What is the difference between <code>cache-from</code> and <code>cache-to</code>, and which one must match the other?	<code>cache-from</code> reads: before building, it looks in the cache for layers to reuse.<br><code>cache-to</code> writes: after building, it saves layers for the next run.<br>The <code>scope</code> must match in both for the same image. If it differs, you read from one slot and write to another, so every run misses.	docker cicd cache
Read this cache value: <code>type=gha,mode=max,scope=backend</code>. What does each key=value pair mean?	It is a comma-separated list of key=value pairs.<br><code>type=gha</code>: where the cache lives (GitHub Actions cache storage).<br><code>mode=max</code>: what to save. <code>max</code> saves all layers of all stages. The default <code>min</code> saves only the final image&#39;s layers. Multi-stage builds need <code>max</code>, because slow steps like <code>npm install</code> sit in an earlier stage. Only used in <code>cache-to</code>.<br><code>scope=backend</code>: the name of the cache slot. Must match in <code>cache-from</code> and <code>cache-to</code>.	docker cicd cache
